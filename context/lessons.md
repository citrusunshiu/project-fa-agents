# Lessons

Each class of defect found, the path it took, which check missed it, and the check that now prevents it. Never the text itself.

- **Pull request text checked only after it was public.** CI checks a pull request's title and body once the pull request exists, which is too late to stop private text. Now text bound for GitHub is written to a file, checked with `tools/check_public_text.py --text`, and posted from the file.
- **Private facts in new words.** The term list catches exact terms, not a private fact said another way. Now every change to this memory gets a cold read by an agent without the private context.
- **An author identity from the agent's environment.** An agent's harness set its own author name and email as environment variables, which override the repository's git configuration. The public-text check caught it on the commit, before any push. Now agents commit with those variables unset, and the check runs over every commit in a push.
- **A check aimed at the wrong repository.** The public-text check always scanned the repository holding it, so running it from a client repository re-checked the hub and reported it clean. Now `--repo` names the repository to scan, and the summary line names the repository it scanned.
- **A check with nothing to look for.** The private-term list is a git-ignored file that linked worktrees don't have, so in a worktree the public-text check loaded no terms and passed, saying so only in its summary line. Now it reads the list from the main checkout and fails when it loads none ([#6](https://github.com/citrusunshiu/project-fa/pull/6)).
- **An allow-list that missed the platform's own identity.** GitHub commits squash merges made on github.com with its own no-reply address, which the check didn't allow, so CI failed on `main` after a merge. Now the address is allowed, and a personal one still fails ([#6](https://github.com/citrusunshiu/project-fa/pull/6)).
- **A check's result lost on the way to the post.** The check and the posting command ran in one shell line where the check's exit status was lost, so issues went up after the check had failed; that time the finding was a false positive. Now agents post only through `tools/post_checked.py`, which runs the check first and runs gh only if it passes, and refuses text it can't check ([#11](https://github.com/citrusunshiu/project-fa/pull/11), [#12](https://github.com/citrusunshiu/project-fa/pull/12)).
- **A push to a pull request that had already merged.** A change pushed to a pull request's branch after it merged never reached `main`, and the push recreated the deleted branch. Now AGENTS.md says to check that a pull request is open before pushing to it or editing it ([#9](https://github.com/citrusunshiu/project-fa/pull/9)).
